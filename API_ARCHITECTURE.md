## Layer-by-Layer Breakdown

### 1. `api/base_url.dart` — Base URL Config

```dart
class BaseUrl {
  static bool isTest = false;
  static String local = "192.168.1.88";
  static const String prod = "3.110.168.50";
  static String get baseurl => "http://${isTest ? local : prod}:8080/";
}
```

- Toggle `isTest` to switch between local dev server and production.
- All endpoints are relative to this base URL.

---

### 2. `api/api_provider.dart` — Retrofit Endpoint Definitions

This is the **single source of truth** for all API paths. Uses the `retrofit` package with annotations.

```dart
@RestApi()
abstract class ApiProvider {
  factory ApiProvider(Dio dio, {String baseUrl}) = _ApiProvider;

  @POST("nephroplus/v1/userLogin")
  Future<LoginResponse> userLogin(
    @Query('email') String email,
    @Query('password') String password,
  );

  @POST("nephroplus/api/change/password")
  Future<CommonResponse> changePassword(
    @Body() ChangePasswordRequest changePasswordRequest,
  );

  @GET("nephroplus/v1/user/profile")
  Future<ProfileResponse> getProfile(
    @Query('userId') String userId,
  );
  // ... all other endpoints
}
```

**Key rules:**

- Every endpoint is defined here with its HTTP method (`@GET`, `@POST`, `@PUT`)
- Query params use `@Query('paramName')`
- Request body uses `@Body()` with a request model class
- Return type is always a response model class (e.g., `Future<LoginResponse>`)
- Path prefix: `nephroplus/v1/...` or `nephroplus/api/...`

---

### 3. `api/api_provider.g.dart` — Generated Code

Auto-generated by running:

```bash
dart run build_runner build --delete-conflicting-outputs
```

**Never edit this file manually.** It implements the abstract `ApiProvider` class using Dio.

---

### 4. `repository/user_repository.dart` — Repository Layer

The repository is the **bridge** between providers and the API layer.

```dart
class UserRepository {
  late ApiProvider _apiProvider;
  late Dio _dio;

  UserRepository() {
    _dio = Dio();

    // Interceptor: Injects auth token + handles 401 (JWT expired)
    _dio.interceptors.add(InterceptorsWrapper(
      onRequest: (options, handler) async {
        if (globalAccessToken != null) {
          options.headers["Authorization"] = globalAccessToken;
        }
        handler.next(options);
      },
      onError: (e, handler) async {
        if (e.response?.statusCode == 401) {
          // Handle token expiry → redirect to login
        }
        handler.next(e);
      },
    ));

    _apiProvider = ApiProvider(_dio, baseUrl: BaseUrl.baseurl);
  }

  Future<LoginResponse> userLogin({required String email, required String password}) async {
    return await _apiProvider.userLogin(email, password);
  }
  // ... wraps every ApiProvider method
}
```

**Responsibilities:**

- Creates Dio instance with interceptors (auth header, 401 handling)
- Wraps every `ApiProvider` method with named parameters for better readability
- Providers call `UserRepository()` — never `ApiProvider` directly

---

### 5. `model/request/` — Request Models

Hand-written Dart classes with manual JSON serialization.

```dart
class ChangePasswordRequest {
  final String? newPassword;
  final String? userId;
  final String? oldPassword;
  final String? userType;

  ChangePasswordRequest({this.newPassword, this.userId, this.oldPassword, this.userType});

  factory ChangePasswordRequest.fromJson(Map<String, dynamic> json) => ChangePasswordRequest(
    newPassword: json["newPassword"],
    userId: json["userId"],
    oldPassword: json["oldPassword"],
    userType: json["userType"],
  );

  Map<String, dynamic> toJson() => {
    "newPassword": newPassword,
    "userId": userId,
    "oldPassword": oldPassword,
    "userType": userType,
  };
}
```

**Pattern for every request model:**

- All fields nullable (`String?`, `int?`)
- `fromJson` factory constructor
- `toJson()` method
- Optional `copyWith()` method
- Export in `request/request.dart` barrel file

---

### 6. `model/response/` — Response Models

Same pattern as request models but for API responses.

```dart
class LoginResponse {
  final int? statusCode;
  final String? message;
  final UserResult? result;

  LoginResponse({this.statusCode, this.message, this.result});

  factory LoginResponse.fromJson(Map<String, dynamic> json) => LoginResponse(
    statusCode: json["status_code"],
    message: json["message"],
    result: json["result"] == null ? null : UserResult.fromJson(json["result"]),
  );

  Map<String, dynamic> toJson() => { ... };
}
```

**Common response structure from backend:**

```json
{
  "status_code": 200,
  "message": "Success",
  "result": { ... }
}
```

- `CommonResponse` is used for simple success/failure responses
- Specific responses (e.g., `LoginResponse`, `ProfileResponse`) have typed `result` fields
- Export in `response/response.dart` barrel file

---

### 7. `provider/` — State Management (ChangeNotifier)

Providers call `UserRepository()` and manage UI state.

```dart
class ProfileProvider extends ChangeNotifier {
  ProfileResult? _profileResult;

  Future<AlertErrorResponse?> getProfileApi() async {
    try {
      ProfileResponse response = await UserRepository().getProfile(userId: globalUserId!);
      if (response.statusCode == 200) {
        _profileResult = response.result;
        notifyListeners();
        return null;
      } else {
        return AlertErrorResponse(alertHeading: "Error!", alertMessage: response.message ?? "");
      }
    } catch (e) {
      return AlertErrorResponse.getErrorResponse(e);
    }
  }
}
```

**Pattern:**

- Extends `ChangeNotifier`
- Private state fields with getters
- API methods return `AlertErrorResponse?` (null = success)
- Calls `notifyListeners()` after state changes
- Try/catch with `AlertErrorResponse.getErrorResponse(e)` for error handling

## How to Add a New API (Step-by-Step)

### Step 1: Create Request Model (if needed)

File: `lib/model/request/your_request.dart`

```dart
class YourRequest {
  final String? field1;
  final int? field2;

  YourRequest({this.field1, this.field2});

  factory YourRequest.fromJson(Map<String, dynamic> json) => YourRequest(
    field1: json["field1"],
    field2: json["field2"],
  );

  Map<String, dynamic> toJson() => {
    "field1": field1,
    "field2": field2,
  };
}
```

Then add export to `lib/model/request/request.dart`:

```dart
export 'your_request.dart';
```

---

### Step 2: Create Response Model

File: `lib/model/response/your_response.dart`

```dart
class YourResponse {
  final int? statusCode;
  final String? message;
  final YourResult? result;

  YourResponse({this.statusCode, this.message, this.result});

  factory YourResponse.fromJson(Map<String, dynamic> json) => YourResponse(
    statusCode: json["status_code"],
    message: json["message"],
    result: json["result"] == null ? null : YourResult.fromJson(json["result"]),
  );

  Map<String, dynamic> toJson() => { ... };
}
```

Then add export to `lib/model/response/response.dart`:

```dart
export 'your_response.dart';
```

---

### Step 3: Add Endpoint in `api_provider.dart`

```dart
@POST("nephroplus/v1/your/endpoint")
Future<YourResponse> yourApiMethod(
  @Query('param1') String param1,    // for query params
  @Body() YourRequest yourRequest,   // for request body
);
```

---

### Step 4: Run Build Runner

```bash
dart run build_runner build --delete-conflicting-outputs
```

This regenerates `api_provider.g.dart` with the new endpoint implementation.

---

### Step 5: Add Method in `user_repository.dart`

```dart
Future<YourResponse> yourApiMethod({
  required String param1,
  required YourRequest yourRequest,
}) async {
  return await _apiProvider.yourApiMethod(param1, yourRequest);
}
```

---

### Step 6: Call from Provider

```dart
Future<AlertErrorResponse?> yourFeatureApi() async {
  try {
    YourResponse response = await UserRepository().yourApiMethod(
      param1: "value",
      yourRequest: YourRequest(field1: "x", field2: 1),
    );
    if (response.statusCode == 200) {
      // Update state
      notifyListeners();
      return null;
    } else {
      return AlertErrorResponse(
        alertHeading: "Error!",
        alertMessage: response.message ?? "",
      );
    }
  } catch (e) {
    return AlertErrorResponse.getErrorResponse(e);
  }
}
```

## Tech Stack Summary

| Layer              | Package/Tool                                          |
| ------------------ | ----------------------------------------------------- |
| HTTP Client        | `dio`                                                 |
| API Abstraction    | `retrofit` (code generation)                          |
| State Management   | `provider` (ChangeNotifier)                           |
| Code Generation    | `build_runner`                                        |
| Auth               | Bearer token via Dio interceptor                      |
| JSON Serialization | Manual (`fromJson`/`toJson`) — no `json_serializable` |

## Suggestions for Better Structure

1. **Separate interceptors** — Move Dio interceptor logic to a dedicated `lib/api/dio_client.dart` or `lib/api/interceptors/auth_interceptor.dart` instead of inside `UserRepository`.

2. **Split repository by domain** — Instead of one giant `UserRepository`, consider:
   - `AuthRepository` (login, OTP, password)
   - `DeviceRepository` (device CRUD, QR, BLE)
   - `CenterRepository` (center list, RO devices)
   - `ProfileRepository` (profile, about)
   - `NotificationRepository` (notifications)

3. **Use `json_serializable`** — For consistency and less boilerplate, use code generation for models too:

   ```dart
   @JsonSerializable()
   class YourRequest {
     final String? field1;
     YourRequest({this.field1});
     factory YourRequest.fromJson(Map<String, dynamic> json) => _$YourRequestFromJson(json);
     Map<String, dynamic> toJson() => _$YourRequestToJson(this);
   }
   ```

4. **Centralize error handling** — Create a base `ApiResult<T>` wrapper instead of returning `AlertErrorResponse?` from every provider method:

   ```dart
   sealed class ApiResult<T> {}
   class Success<T> extends ApiResult<T> { final T data; }
   class Failure<T> extends ApiResult<T> { final String message; }
   ```

5. **Environment config** — Use `--dart-define` for base URL instead of a static `isTest` flag:

   ```bash
   flutter run --dart-define=BASE_URL=http://192.168.1.88:8080/
   ```

6. **Add API path constants** — Instead of hardcoding paths in annotations, define them in a constants file for easier searching and refactoring.
